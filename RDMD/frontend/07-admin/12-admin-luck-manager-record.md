## 화면

- **회원 목록**: 닉네임 검색(관리자 이름 포함)·전체 보기, 20명씩 페이지(`AdminPagination`), 최근 활동 순.
  열 = 닉네임(+이메일) · 보유 포인트 · 행운 티어 횟수 · 최고 티어 · 포커 판수 · 랜덤 뽑기 배팅 수 · 최근 활동 · **기록 보기**. 위쪽에 이용 회원 수·전체 보유 포인트 합계.
- **기록 보기** → 아래에 상세 패널(다시 누르면 접힘, 한 번에 한 명). 요약 카드 6개 + 탭 4개:
  - 오늘의 행운 티어 — 티어별 누적 문구 + 최근 기록 표(최대 5건, 보관 정책 안내 문구)
  - 행운 티어 포커 — 시각·배팅·결과 배지(승리/패배/무승부/진행 중/기록 없음)·족보(나 vs 딜러)·지급·순증감, 최근 50판
  - 랜덤 뽑기 — 시각·회차·배팅 종류·금액×배수·라운드 결과·결과 배지·증감, 최근 50건
  - 포인트 내역 — 얻은/사용·잃은 합계 카드, 출처별 합계 표, 원장 표(시각·출처·내용·증감·잔액) 30건씩 페이지
- 증감은 +초록 / -빨강, 다크 테마 색 별도. 진행 중인 포커 판은 순증감 칸에 차감된 배팅액(-)을 보여준다.
- **지갑 주인 배지**: [관리자](파랑) / [탈퇴](회색), 일반 회원은 배지 없음 — 처음엔 서버가 회원만 찾아 관리자 지갑이 "(탈퇴 회원)"으로 나왔고, 같은 날 서버가 관리자도 찾도록 고치면서 배지를 붙였다. 관리자 로그인은 토큰을 `authToken` 에도 저장해(`AdminLogin.jsx`) 관리자가 뽑으면 지갑이 Admin id 로 생기기 때문.
- 정적 미리보기(`isStaticPreview`)에서는 요청하지 않고 안내만 보인다.

## 확인

- 가짜 서버(빌드된 `dist` + 가짜 API, 운영 DB 미접속)에 Chrome DevTools Protocol 로 붙어 목록·탭 4개를 열고 캡처해 확인.
  확인 중 한 번 개발용 포트(5173)로 띄워 프론트가 API 를 `localhost:5000`(운영 DB 를 쓰는 로컬 서버)으로 보냈다 — 조회(GET)만 했고 데이터 변경 없음. 이후 개발 포트와 겹치지 않는 포트로 다시 확인.
- 로컬 서버가 새 API 추가 전에 켜져 있어 `404` 가 났던 일 — Node 는 켜질 때 코드를 읽으므로 서버를 다시 켜서 해결(빌드된 화면은 요청 때마다 디스크에서 새로 읽어 화면만 먼저 바뀌었음).
- 로컬 서버(새 코드, 운영과 같은 DB)에 관리자 토큰으로 회원 목록을 요청해 지갑 4개(회원 2·관리자 1·탈퇴 1)·관리자 지갑 상세 "관리자" 표시 확인. 운영 배포 후에는 3개 주소에서 비로그인 요청이 401(경로 존재)인 것까지만 확인.
