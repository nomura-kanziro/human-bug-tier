# 커밋 요약 — 이벤트 페이지 신설(매일 퀴즈 · 티어표 공개(뼈대) · 메모리 게임) + 로고 조명 다크 모드 한정

## 요청

> 1. 테마 설정에서 어두움 상태 때 라이트 적용된 로고가 **밝음 상태에서는 라이트 기능이 없고 어두움 상태일 때만** 켜지도록.
> 2. **이벤트 페이지**를 만들고 그 안에 3종을 넣을 것.
>    - **매일 간단 퀴즈** — "{캐릭터}는 어느 티어인가요?" 3지선다(티어 + 갑·을·병·정 급까지). 맞히면 1~1000P를
>      복권 형태로, **1~5P가 가장 흔하고 숫자가 클수록 확률이 낮게**.
>    - **제작한 티어표 공개** — 관리자가 열고 닫고 마감 시간을 정하며, 마감되면 등록 버튼이 닫히고 30분~1시간 뒤
>      또는 관리자가 직접 결과 공개. 공개되면 **참여한 모든 유저에게 알림**.
>      다만 **뼈대만 만들고 정식 발매 X — 관리자만 들어갈 수 있게.**
>    - **메모리 게임** — 4×4 → 6×6 → 8×8 3단계, 클리어하면 이벤트 안에 기록 저장. 특정 기간 최고 기록에 1000P 이상.
> 3. 푸시 금지.

## 1. 로고 조명(halo)을 다크 모드에서만

로고 `logo.webp` 는 **투명 배경에 어두운 잉크 엠블럼**이라(불투명 픽셀 평균 밝기 37/255) 어두운 배경 위에서는
형체가 거의 안 보인다. 그래서 직전 로딩 화면 작업(`eee7550`)에서 뒤에 은은한 원형 조명을 깔았는데, 그 규칙이
`Header_Footer.css` 안의 `.logo-img`(헤더 로고) **한 자리에만** 걸려 있었다. 그 결과

- 푸터·홈 인트로·로그인 화면의 같은 로고에는 조명이 안 들어오고,
- 규칙이 파일 여기저기 흩어질 위험이 있었다.

조치: 조명 규칙을 **`app-shell.css` 한 곳**(`[data-theme="dark"]` 아래)으로 모으고 헤더·푸터 로고를 함께 걸었다.
`Header_Footer.css` 의 원래 자리에는 기존 주석을 지우지 않고 "실제 규칙은 app-shell.css 에 있다"는 안내만 남겼다.
**밝음 상태에는 규칙 자체가 없다** — 원본 그대로가 가장 또렷하기 때문.

확인(CDP 실측, 계산된 스타일 직접 조회):

| 테마 | 헤더 로고 | 푸터 로고 | 홈 인트로 | 로그인 화면 |
|------|-----------|-----------|-----------|-------------|
| 밝음 | `background: rgba(0,0,0,0)` / `filter: none` | 동일 | 동일 | 동일 |
| 어두움 | radial-gradient + `drop-shadow(...) brightness(1.08)` | 동일 | 동일 | 동일 |

## 2. 이벤트 페이지 (`/event`)

헤더 메뉴의 "• 이벤트 (준비 중)" 를 실제 링크로 바꿨다. 페이지는 행운 뽑기와 같은 **URL 해시 탭** 방식이라
`/event#quiz`, `/event#showcase`, `/event#memory` 로 특정 탭을 바로 열 수 있다.

### 2-1. 매일 간단 퀴즈 (`EventQuizPanel.jsx`)

- 문제·정답·상금은 **전부 서버가 정한다.** 프론트는 고른 보기 번호만 보내고, 아직 안 푼 문제의 정답은
  응답에 아예 들어오지 않는다(정답을 미리 받아두면 개발자 도구로 보인다).
- 보기 3개는 "3티어 을급"처럼 **티어 + 급**까지 표시한다.
- 채점 후에는 정답 보기를 초록, 내가 고른 오답을 빨강으로 표시하고, 상금 확률표를 함께 보여준다.
- 하루 1회라 새로고침해도 결과 화면이 유지되고 제출 버튼은 사라진다.

### 2-2. 제작한 티어표 공개 (`EventShowcasePanel.jsx`) — **뼈대 · 관리자 전용**

- 일반 회원에게는 "준비 중" 안내 블록만 보이고, 관리자에게만 회차 관리 폼(제목·설명·마감 시각·결과 공개 예정 시각,
  저장 / 접수 열기 / 접수 닫기 / 지금 결과 발표, 참가자 목록, 당첨자)이 보인다.
- 화면에도 "정식 공개 전 — 관리자만 접근" 안내를 띄워 둔다. 서버도 같은 라우트를 `requireAdmin` 으로 막아
  **화면만 숨긴 게 아니다**.

### 2-3. 메모리 게임 (`EventMemoryPanel.jsx`)

- 4×4(16장) → 6×6(36장) → 8×8(64장) 3단계를 이어서 진행한다.
- 기록이 순위·포인트로 이어지므로 **시간은 프론트가 보내지 않는다.** 서버가 시작·단계 통과 시각을 자기 시계로 찍고
  총 기록도 서버가 계산한다. 프론트는 서버가 내려준 배치를 그리고 "이 단계 다 맞췄다"는 신호만 보내며,
  화면의 타이머는 보여주기용이다.
- 완주하면 총 기록 + 단계별 기록이 나오고 순위표가 갱신된다. 새로고침하면 그 판은 무효(서버 세션이 끊긴다).

### 캐릭터 이미지 경로 (작업 중 발견한 버그)

서버는 `tier-image/6 tier/mamiya kyohei.webp` 처럼 **접두사와 공백이 섞인 경로**를 내려준다. 처음에 이 값을
`<img src>` 에 그대로 넣어 퀴즈·메모리 카드 이미지가 전부 깨졌다. 행운 뽑기/사다리와 마찬가지로
`lib/paths.js` 의 `tierImageUrl()` 로 감싸 해결했다(접두사 정리 + `encodeURI`).
→ `/tier-media/tier-image/6%20tier/mamiya%20kyohei.webp`

## 확인 (실제 Chrome · CDP)

브라우저 테스트 27건 전부 통과.

- 헤더에 `/event` 링크 노출
- 퀴즈: 보기 3개, 문구 "어느 티어인가요?", 보기 형식 "N티어 X급", 캐릭터 이미지 **실제 로드**(`naturalWidth > 0`),
  고르기 전 제출 비활성 → 정답 클릭 → 포인트 지급 문구·보유 포인트 반영·정답 강조·확률표 7줄,
  새로고침해도 하루 1회 유지
- 메모리: 카드 16 → 36 → 64장, 카드 앞면 이미지 실제 로드, 타이머 진행, 완주 결과(총 기록 21.95초 / 단계별 3줄),
  순위표 반영, 서버 저장 기록과 화면 값 일치
- 티어표 공개: 일반 회원 = "준비 중"만 · 관리자 입력 폼 비노출 / 관리자 = 회차 관리 폼 + "정식 공개 전" 안내

테스트에 쓴 임시 계정·기록은 모두 삭제했다.

## 알려진 한계

- 티어표 공개는 **뼈대**다. 참가 작품을 고르는 UI(내 커스텀 티어표 선택)와 당첨자 선정 기준은 정식 공개 때 붙인다.
- 메모리 게임 순위 기간은 관리자가 정산 API 를 호출하는 방식이라 자동 기간 마감은 아직 없다.
- 퀴즈는 캐릭터 단위 랜덤이라 같은 캐릭터가 며칠 뒤 또 나올 수 있다(하루 1문제라 체감은 낮다).
