## 판단

### 제보 채널을 문의하기에서 뺐다

- 이전 `SECURITY.md` 는 "사이트 문의하기로 비공개 연락"이라고 안내했는데, **문의 목록 API(`GET /api/inquiries`)는 인증 없이 전체를 돌려준다.** 문의하기는 비공개 채널이 아니므로 보안 제보에 쓰면 안 된다.
- 그래서 GitHub 비공개 취약점 제보와 "세부 내용 없이 먼저 연락"으로 바꿨다. 문의하기를 쓰는 곳에는 개인정보·보안 내용을 쓰지 말라는 경고를 넣었다.
- 비공개 제보는 창시자가 저장소 설정에서 켜야 동작한다(체크리스트에 있음).

### 보안 장치 표는 확인한 것만

- bcrypt 10, JWT 회원 7일 · 관리자 24시간, 재설정 토큰 `randomBytes(32)` + SHA-256, 이메일 인증 1시간, `Block`(회원·IP), AI `127.0.0.1` + `X-AI-Key` + IP당 10분 20회, 요청 크기 2MB · 5MB, `deploy.sh package` 의 `.env*` 제외를 코드로 확인했다.
- 지켜지지 않는 것을 지킨다고 쓰지 않았다. 아직 하지 않은 것(예: 로그인 시도 제한)은 약속하지 않았다.
- 공개 저장소이므로 **미해결 취약점의 구체 내용은 문서에 적지 않았다.**

### 법적 조항은 초안

- 소유권·기여물 귀속, 준거법(대한민국), 선의의 제보 면책, 응답 목표(영업일 3일)는 창시자가 정할 값을 기본값으로 넣은 것이다. 법률 검토를 받은 문서가 아니므로 필요하면 전문가 확인을 거친다.
- 저장소가 공개 상태이면 이 문서들은 금지의 근거일 뿐 clone 을 막지 못한다는 점을 `CONTRIBUTING.md` 7절에 명시했다.

## 알려진 한계

- 서버의 실제 설정(JWT_SECRET 설정 여부, SSH 키 인증만 허용 여부, 열린 포트)은 서버에 접속하지 않아 확인하지 못했다. 체크리스트로 남겼다.
- GitHub 에서의 실제 표시는 푸시 전이라 확인하지 못했다.
