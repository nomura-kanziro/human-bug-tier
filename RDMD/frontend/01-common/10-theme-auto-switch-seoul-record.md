# 커밋 요약 — 테마 자동 전환을 서울 시각 기준 + 만료형 수동 선택으로 재설계

## 개요

"22시가 되면 다크, 오전 7시가 되면 라이트" 자동 전환이 제대로 적응(동작)하지 않는다는 지적과
"시간도 한국 서울 기준으로 하자"는 요청에 따라 `src/lib/theme.js` 와 `index.html` 의 첫 렌더 전
스크립트를 다시 만들었다. 원인은 두 가지였다.

## 원인

| # | 증상 | 원인 |
|---|------|------|
| 1 | 서울과 다른 시각에 바뀜 | `new Date().getHours()` — **접속한 브라우저의 시간대**를 읽었다. 해외 접속·PC 시간대가 다른 경우 서울 22시가 아닌 다른 시각에 바뀌었다 |
| 2 | 한 번 눌러 본 브라우저는 영영 안 바뀜 | 토글을 누르면 `localStorage.hbtTheme` 에 `'light'\|'dark'` 가 **영구 고정**됐고, 자동으로 돌아가는 `resetThemeToAuto()` 는 **어디서도 호출되지 않았다** |
| 3 | 전환이 최대 30분 늦음 | 30분 주기 폴링 |

## 변경된 파일 목록

- Modified: `root-cloudflare/src/lib/theme.js` (전면 재작성)
- Modified: `root-cloudflare/index.html` (첫 렌더 전 인라인 스크립트 — theme.js 와 같은 규칙)

## 새 규칙

- **자동값**: 서울 시각(UTC+9) 기준 07:00~22:00 라이트, 22:00~다음날 07:00 다크. 한국은 서머타임이 없어
  고정 오프셋(`Date.now() + 9h` 의 UTC 시)으로 계산하므로 `Intl` 시간대 데이터에 의존하지 않는다.
- **수동 선택은 "다음 자동 전환 시각까지만"** 유지된다. 낮에 다크로 눌러 두면 22:00 까지, 밤에 라이트로
  눌러 두면 다음 날 07:00 까지. 그 시각이 지나면 저장값이 지워지고 자동 규칙으로 돌아간다.
  지금 자동값과 같은 쪽으로 다시 토글하면 고정 저장 자체를 지운다.
- **저장 형식**: `hbtTheme = {"t":"light"|"dark","u":<만료 epoch ms>}`. 만료 필드가 없거나 깨진 값은
  무시(= 영구 고정이 다시 생기지 않게).
- **예전 사용자 이어받기**: 예전 형식(`'dark'` 문자열)은 읽는 순간 "다음 전환 시각까지"짜리 JSON 으로
  바꿔 준다. 이미 영구 고정돼 있던 브라우저도 다음 전환 시각에 자동으로 풀린다.
- **정확한 시각 전환**: 다음 07:00/22:00 서울 시각에 맞춰 `setTimeout` 을 예약(+1초)한다.
  백그라운드 탭·절전에서 타이머가 밀릴 수 있어 탭 복귀(`visibilitychange`)·창 포커스에서도 다시 계산하고,
  다른 탭에서 토글하면 `storage` 이벤트로 같이 맞춘다.

> ⚠ **`index.html` 인라인 스크립트는 `theme.js` 의 규칙을 그대로 복제**한다(CSS·React 가 뜨기 전에 색을 정해
> 깜빡임을 막아야 해서 모듈을 import 할 수 없다). 전환 시각(7/22)이나 저장 형식을 바꾸면 **두 곳을 같이** 고쳐야 한다.

## 테스트

- **단위(Node, 시간대 5종)**: `America/Los_Angeles`·`Asia/Seoul`·`Asia/Tokyo`·`Europe/London`·`Pacific/Auckland`
  에서 같은 서울 시각이 같은 결과를 내는지(경계 06:59:59/07:00, 21:59:59/22:00, 월말·연말·2월 말 넘김,
  예전 형식 이어받기·만료·깨진 값·만료 필드 없는 값) 25건 통과.
- **브라우저(Chrome)**: 브라우저 시간대를 LA 로 바꾸고 가짜 시계로 서울 시각을 지정해 검증 21건 통과.
  - 서울 23:00(LA 로는 07시) → 다크, 서울 05:00(LA 13시) → 다크 — 예전 코드면 라이트로 나왔을 시각
  - 예전 영구 고정 사용자는 다음 날 08:00 에 라이트로 복귀
  - 토글은 서울 22:00 까지로 저장, 새로고침해도 유지, 자동값과 같아지면 저장 삭제
  - 전환 타이머가 22:00 에 맞춰 예약(21:59:00 로드 → 약 61초), **21:59:57 에서 시작해 아무것도 안 눌러도 22:00:01 에 다크 전환**
- 첫 렌더 전 스크립트는 `/assets/*.js` 를 막아 React 없이 그 스크립트만의 결과를 따로 확인했다.

## 알려진 한계

- 다른 탭 동기화(`storage` 이벤트)는 구현했지만 이번에 자동 테스트하지 않았다.
- `root-render/`(바닐라, 수정 금지)의 `theme.js` 는 예전 규칙 그대로다. 같은 origin 에서 함께 쓰면 새 JSON 형식을
  모르는 값으로 보고 자동값으로 처리하므로 깨지지는 않는다.
