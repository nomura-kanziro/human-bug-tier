# 커밋 요약 — 로딩 화면: React 쪽에서 "적용은 됐지만 안 보이던" 것을 실제 대기 구간에 보이게

## 질문과 결론

> Render.com(바닐라)의 로딩 화면 애니메이션이 지금 Cloudflare(React) 쪽에도 적용돼 있나?

**컴포넌트·CSS 는 옮겨져 있었지만, 실제 로딩 구간에는 거의 보이지 않았다.** 그래서 고쳤다.

| | 바닐라 (`root-render`) | React (이전) | React (지금) |
|---|---|---|---|
| 오버레이 위치 | `index.html` 에 **정적 마크업** | React 가 직접 렌더 | `index.html` 정적 마크업 |
| 처음 보이는 시점 | 첫 화면부터 | **JS 번들(351KB)이 내려와 실행된 뒤** | 첫 화면부터 |
| 사라지는 시점 | 헤더·푸터가 자리 잡은 직후 | 마운트 직후 0ms + 페이드 | 앱이 그려진 직후(최소 표시 시간 없음) |
| 결과 | 기다리는 동안 보임 | 기다리는 동안 **빈 화면**, 오버레이는 0.3초 번쩍 | 기다리는 동안 보임 |

느린 네트워크(1.6Mbps/지연 150ms) 실측: 이전에는 첫 페인트 1.9초·오버레이는 **3.2초에야 생겨 0.3초만** 떠 있다가 사라졌고,
1초 시점 캡처는 완전한 빈 화면이었다.

## 변경된 파일 목록

- Modified: `root-cloudflare/index.html` (정적 오버레이 마크업 + 안내 문구 + 15초 스크립트, 폰트 CSS 비차단화)
- Modified: `root-cloudflare/src/components/LoadingScreen.jsx` (그리는 컴포넌트 → 치우는 컨트롤러)
- Modified: `root-cloudflare/src/styles/loading-screen.css`
- Modified: `root-cloudflare/src/main.jsx` (CSS import 제거), `src/components/AuthShell.jsx` (중복 `<LoadingScreen />` 제거)
- Added: `root-cloudflare/public/tier-media/tier-image/logo-loading.webp` (240px 사본, 31KB)

## 작업 조건 — "일부러 2초 이상 지연하지 않는다"

- **최소 표시 시간이 없다.** 앱이 그려지는 즉시 치운다(느린 4G 실측: 앱이 뜬 뒤 **약 150ms** 만에 제거 — 이 중 150ms 는 페이드).
- **빠르면 아예 안 보인다.** 오버레이는 처음 80ms 동안 투명하게 시작해 나타난다. 캐시가 있어 앱이 80ms 안에 뜨면
  (`LoadingScreen.jsx` 가 그 경우 페이드 없이 즉시 제거) 번쩍임 없이 안 보인다. 제한 없는 환경 실측: 앱 42ms, 오버레이 한 번도 안 보임.
  (처음엔 프레임 두 번을 기다리게 짰다가 빠른 환경에서 160ms 깜빡이는 걸 실측으로 잡아 프레임 대기를 뺐다.)
- **정말 오래 걸릴 때만 오래 보인다.** 실제 로딩이 끝날 때까지만 떠 있고, 6초가 넘으면 "생각보다 오래 걸리고 있어요" 안내가 서서히 나타난다.
  앱이 끝내 안 뜨면(번들 다운로드 실패 등) 오버레이는 유지하되 15초 뒤 "새로고침(F5)" 안내로 바뀐다(빈 화면을 노출하지 않음).
- 캐릭터 이미지 수십 장은 기다리지 않는다(바닐라와 같은 기준 — 페이지를 쓸 수 있는 시점).

## 작업 중 발견한 성능 문제 (오버레이가 만든 것 포함)

오버레이를 첫 화면부터 띄우자 앱이 뜨는 시각이 3.2초 → 5.5초로 늦어졌다. 원인을 하나씩 추적해 잡았다.

1. **오버레이 글자가 웹폰트(Pretendard) 다운로드를 유발** → 좁은 회선에서 JS 번들과 대역폭 경쟁. 오버레이는 시스템 폰트로 고정. (5.5 → 4.8초)
2. **`logo.webp` 가 519KB** (앱 JS 번들보다 큼) 인데 오버레이가 첫 화면부터 이걸 받았다 → 240px 사본 `logo-loading.webp`(31KB)를 만들어 사용. (4.8 → **3.2초**, 원래 수준)
3. **외부 CDN 폰트 CSS 가 렌더 차단** — 직전 디자인 작업(`22ec329`)에서 넣은 것. `media="print" onload` 비차단 로드로 변경(`font-display: swap` 확인).

최종: 느린 4G 에서 첫 페인트 2.0초 → 앱 3.2초, 오버레이는 그 사이(약 1.3초) 보이고 앱이 뜬 직후 사라진다.

## 그 밖에

- 페이지 바탕색(`html`)을 테마 색으로 먼저 깔아 다크 모드 첫 화면이 흰색으로 번쩍이지 않게 했다.
- 다크 모드에서 로고(투명 배경 + 검은 잉크)가 어두운 바탕에 묻혀 링 글로우만 보이던 것(이전 React 오버레이 때부터 있던 문제)을 밝은 원형 바탕으로 고쳤다.
- 오버레이 CSS 는 `index.html` 에 `<link>` 로 걸었지만 Vite 가 앱 번들 CSS 에 합친다(별도 파일로 안 나옴). 그래도 JS 번들은 이제 첫 화면을 막지 않는다.

## 테스트

- 라우트 8개(`/ /login /signup /board /tier/5 /luck-draw /notice /contact`) × 라이트/다크 = 16건: 앱이 뜬 뒤 오버레이가 DOM 에서 제거됨
- 느린 4G: 앱이 뜬 뒤 500ms 이내 제거(실측 약 150ms), 로딩 중 오버레이가 실제로 화면에 보임(라이트·다크)
- 앱이 정상적으로 뜨면 6초 안내를 띄우지 않음 / JS 차단 시: 오버레이 유지 → 약 7초에 "오래 걸리고 있어요" → 15초 뒤 "새로고침" 안내
- 직전 작업(테마 자동 전환) 회귀 테스트 21건 통과

## 알려진 한계 / 참고

- 첫 페인트는 앱 번들 CSS(145KB)를 기다린다(렌더 차단). 오버레이 CSS 만 인라인해도 앱 CSS 링크가 막고 있어 이득이 없고, 앱 CSS 를 비차단으로
  바꾸면 CSS 보다 JS 가 먼저 도착할 때 스타일 없는 화면이 노출될 수 있어 손대지 않았다.
- **`logo.webp` 519KB 는 사이트 전체(헤더·파비콘)에서 그대로 쓰인다.** 오버레이만 사본으로 돌렸고, 사이트 로고 자체를 줄이는 것은 이번 범위 밖이다(별도 개선 후보).
- SPA 안에서 라우트를 옮길 때(링크 클릭)는 오버레이가 뜨지 않는다 — 바닐라(페이지 전체 이동)와 다른 점이며, 이전 React 구현도 마찬가지였다.
