# 커밋 요약 — 티어표 공개: 접수 시작 시 전체 회원 알림 + 결과 발표 36시간 뒤 자동 초기화

## 요청

> 어제 하다만 작업 — 티어표 공개에서 이벤트 진행 후 대회에서 결과가 나온 36시간 뒤에 자동으로 결과 발표 내용이 사라지고 원 상태로 초기화되는 것.
> 그리고 이벤트 접수 시작 시 무조건 모든 유저에게 알림이 갈 수 있도록.

## 1. 결과 발표 36시간 뒤 자동 초기화

`SHOWCASE_RESULT_EXPIRE_MS = 36시간`. 스케줄러(`advanceShowcases`, 1분마다 + 조회 때마다 실행)에 마지막 단계로 추가했다 —
`status: 'revealed'` 이고 `revealedAt` 이 36시간을 넘긴 회차를 찾아 **투표 → 출품 → 회차 문서 순서로 완전히 삭제**한다.
"원 상태로 초기화"를 문자 그대로 — 별도 상태로 남기거나 보관하지 않고, **이 회차가 아예 없었던 상태**로 되돌린다(관리자 목록에서도 사라짐).
상금 지급·참가자 알림은 이미 발표 시점에 끝났으므로 삭제 자체는 별다른 알림 없이 조용히 처리한다.

## 2. 접수 시작 시 전체 회원 알림

`notifyShowcaseOpened(showcase)` 를 새로 만들어 **회차가 `open` 상태가 되는 두 지점 모두**에서 호출한다.

- 스케줄러가 예약 시각(`opensAt`)이 되어 자동으로 여는 경우 (`advanceShowcases` 의 `scheduled → open`)
- 관리자가 관리자 페이지에서 "지금 접수 열기"를 누른 경우 (`POST /showcase/status { action: 'open' }`)

`User.find()` 로 **조건 없이 회원 전체**를 돌며 `Notification` 타입 `event_open`(신규 enum 값), 카테고리 `noticeNews` 로 알림을 만든다.
"무조건"이라고 했지만 사이트 공통 규칙(개인 알림 설정에서 공지·소식 카테고리를 꺼둔 사람에게는 안 보냄)은 그대로 지킨다 —
전체 알림 기능이 개인 설정을 무시하기 시작하면 그 규칙 자체가 무의미해지므로, 여기서 "무조건"은 "참가자만이 아니라 회원 전체"로 해석했다.

**중복 알림 방지**: 스케줄러(1분 주기)와 관리자의 수동 "지금 열기"가 같은 순간 겹칠 수 있어, 두 지점 모두
`EventShowcase.findOneAndUpdate({ _id, status: 'scheduled' | { $in: ['draft','scheduled'] } }, { $set: { status: 'open', ... } })`
로 **상태 전환을 원자적으로 선점**한 뒤 그 결과(claimed)에 대해서만 알림을 보낸다 — 한쪽이 실패하면(이미 다른 쪽이 선점) 조용히 넘어가거나
관리자에게는 409 로 안내한다(발표 때 상금이 중복 지급되지 않도록 만든 것과 같은 패턴).

## 주요 파일

| 파일 | 내용 |
|------|------|
| `backend/models/Notification.js` | `type` enum에 `event_open` 추가 |
| `backend/controllers/eventController.js` | `SHOWCASE_RESULT_EXPIRE_MS`, `notifyShowcaseOpened()`, `advanceShowcases()` 의 자동 오픈·36시간 만료 처리, `setShowcaseStatus` 의 `open` 액션 원자화 |

## 확인

**36시간 자동 초기화** — API 테스트 8건 통과: 35시간 59분 지난 회차는 그대로 유지(출품·투표 포함), 36시간 1분 지난 회차는 회차·출품·투표까지
전부 삭제, 진행 중(open)인 다른 회차는 영향받지 않음, 삭제 후에도 현황 조회가 계속 정상 동작.

**전체 회원 알림** — 이 기능은 **실제 서비스에 등록된 회원 13명 전원**에게 진짜 알림을 보내는 기능이라, 자동화된 회귀 테스트로 실제 발송을
반복시키지 않았다(테스트를 여러 번 돌릴 때마다 실제 회원에게 스팸이 가는 것을 피하기 위함). 대신,

- `notifyShowcaseOpened` 와 완전히 같은 `createNotification` 호출을 임시 계정 2명(알림 전체 켜짐 / `noticeNews` 꺼둠)에게만 실행해
  새 enum 값이 스키마를 통과하는지, 카테고리·제목·메시지·링크가 맞는지, **개인 알림 설정을 여전히 존중하는지**(꺼둔 사람에게는 안 감)를 검증했고,
- 소스 코드를 읽기 전용으로 검사해 `notifyShowcaseOpened` 가 `User.find()`(필터 없음)로 전체 회원을 돈다는 것, 접수 시작 두 지점 모두에서
  호출된다는 것, 두 지점 모두 원자적 선점 패턴을 쓴다는 것을 확인했다.

작업 도중 서버를 재시작하며 스케줄러가 처음 돌자, **정말로 이미 36시간이 지나 있던 실제 회차 1건("테스트", 2026-09-21 생성분)이
자동으로 삭제됐다** — 요청한 기능이 정확히 의도대로 동작한 것이지만, 실제 데이터에 영향을 준 것이므로 별도로 알린다(작업 보고 참고).

## 알려진 것

- 36시간 자동 삭제는 되돌릴 수 없다(회차·출품·투표 기록이 통째로 사라짐). 관리자가 발표 결과를 더 오래 보관하고 싶다면 36시간 안에
  스크린샷 등으로 따로 기록해야 한다.
- "전체 회원 알림"은 이메일 인증 여부와 무관하게 `User` 컬렉션의 모든 계정에 간다(참가·투표 자격과 달리 알림은 미인증 회원도 받는다 — 계정을 만든 이상 새 이벤트가 열렸다는 소식은 알 자격이 있다고 보았다).
