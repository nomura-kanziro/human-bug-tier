# 커밋 요약 — 매일 퀴즈 기록을 회원당 최근 15건만 보관

## 요청

> 이벤트 퀴즈 맞추기 MongoDB 에 저장할 때 데이터 15개 이상 되면 가장 오래된 데이터는 자동으로 지우도록.

## 관련 커밋

- `ab1728b` (2026-10-01) feat(event): 매일 퀴즈 기록을 회원당 최근 15개만 남기고 오래된 것부터 자동 삭제

## 배경

`EventQuizAttempt` 는 회원 1명 × 하루 1판(`{userId, quizDate}` unique)이라 회원마다 하루 1건씩 끝없이 쌓였다.
지난 기록은 어디서도 읽지 않는다 — `/quiz/today`(오늘 문제)와 `/quiz/answer`(채점)만 오늘 문서를 쓰고, 상금은 지급 즉시 `LuckProfile.points` 에 더해진다.

## 구현 (`backend/controllers/eventController.js`)

- `QUIZ_HISTORY_RETENTION = 15` — 회원당 남길 개수(이 숫자만 바꾸면 조정).
- `pruneQuizHistory(userId)` — 그 회원 기록을 `quizDate` 내림차순(KST `YYYY-MM-DD` 문자열이라 문자열 정렬 = 날짜 순)으로 정렬해 16번째부터 삭제. 행운 뽑기 이력 정리(`pruneLuckHistory`)와 같은 방식.
- 호출 시점: `getQuizToday` 에서 **오늘 문제가 새로 만들어졌을 때만**. 정리 실패는 로그만 남기고 오늘 문제는 그대로 응답.
- "15개 이상이면 지운다"를 **최대 15건 보관**으로 해석(16번째가 생기면 가장 오래된 것 삭제). 14건만 남겨야 하면 상수를 14로.

## 안전성

- 회원별 기준 — 다른 회원 기록에 영향 없음.
- 오늘 문제가 항상 가장 최신이라 지워지지 않음 → 하루 1회 제한 유지.
- 지난 기록을 집계하는 곳이 없어 포인트·통계 영향 없음(받은 상금은 지갑과 포인트 원장 `LuckPointLog` 에 남는다 — 2026-10-01 원장 추가 이후).
- 이미 15건을 넘은 회원은 다음에 퀴즈를 열 때 정리된다.

## 확인

- 운영 DB 를 건드리지 않고 가짜 모델로 정리 함수 실행: 20일치 → 오래된 5건 삭제, 최근 15건(09-06~09-20) 유지, 다른 회원 기록 유지.
- 서버 로드 확인. 커밋은 같은 파일의 포인트 원장 변경과 분리하기 위해 퀴즈 정리 부분만 먼저 커밋했다.
