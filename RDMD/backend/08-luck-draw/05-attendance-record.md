# 출석체크 — 로그인할 때마다 하루 1회 10포인트 (자동)

## 요청

> 한국 시간으로 자정 00시 당일 내로 다음날 00시 이전까지, 로그인할 때마다 하루에 한 번 출석체크로 10포인트를 지급. 자동화할 것.

## 동작

- 회원이 **로그인에 성공하면 서버가 알아서** 그날(KST 00:00~24:00) 첫 로그인인지 판단해 **10포인트**(행운 뽑기 포인트 = `LuckProfile.points`)를 넣는다. 누르는 버튼·신청 없음.
- 같은 날 다시 로그인해도 지급하지 않고, **한국 시간 자정이 지나면** 다음 로그인에서 다시 받는다(23:59 로그인 + 00:00 로그인 = 하루 두 번 받을 수 있는 건 날짜가 달라서이며 정상).
- 로그인 응답에 `attendance: { granted, points, balance, date }` 가 같이 내려가고, 프론트(`Login.jsx`)는 지급됐을 때만 "📅 출석체크 완료! +10P (보유 nP)" 를 로그인 성공 알림에 덧붙인다.
- 관리자 로그인에는 적용하지 않는다(관리자는 별도 토큰 체계·포인트 지갑 없음).

## 구현

| 파일 | 내용 |
|---|---|
| `backend/utils/attendance.js` (신규) | `grantDailyAttendance(userId)` — `LuckProfile.findOneAndUpdate({userId, lastAttendanceDate:{$ne:오늘}}, {$set:{lastAttendanceDate:오늘}, $inc:{points:10}}, {upsert:true})`. **판정과 지급이 한 번의 원자적 갱신**이라 같은 계정이 동시에 여러 번 로그인해도 한 번만 들어간다. 오늘 이미 받았으면 조건에 안 맞아 upsert 가 같은 `userId` 를 만들려다 unique 오류(11000)가 나는데 이를 "이미 받음"으로 처리한다. 어떤 오류도 던지지 않는다 → **출석체크 때문에 로그인이 실패하지 않는다** |
| `backend/models/LuckProfile.js` | `lastAttendanceDate`(String, KST `YYYY-MM-DD`, 기본 빈 문자열) 추가. 기존 문서는 필드가 없어도 `$ne` 에 걸려 정상 지급 |
| `backend/models/LuckPointLog.js`, `adminLuckController.js` | 원장 `source` 에 `attendance` 추가, 관리자 포인트 내역 라벨 "출석체크" |
| `backend/controllers/authController.js` | `login` 이 토큰 발급 직후 호출, 응답에 `attendance` 포함 |
| `root-cloudflare/src/pages/Login.jsx` | 지급 안내 문구 |

날짜 경계는 `utils/kstDate.js`(UTC+9)를 그대로 써서 서버 시간대와 무관하다. 지급 내역은 포인트 원장(`detail`: "출석체크 (날짜)")에 남아 관리자 "행운 뽑기 관리 → 포인트 내역"에서 보인다.

## 확인

- `LuckProfile`/원장을 대체한 테스트용 가짜 저장소로 `grantDailyAttendance` 를 시각만 바꿔 호출: KST 10-17 23:59 지급 → 같은 날 재호출 거절 → KST 10-18 00:00(UTC 15:00) 지급 → 같은 날 23:59:59 거절 → 다른 유저 지급, 원장 3건. 컨트롤러 모듈 로드 확인.
- **실제 MongoDB 로는 시험하지 못했다**(로컬 DB 없음, 운영 DB 에 시험 계정을 만들지 않음). "이미 받은 문서에 upsert 하면 11000" 은 MongoDB 의 표준 동작에 기댄 부분이라, 배포 후 실제 로그인으로 확인이 필요하다.
- 운영 배포는 하지 않았다(커밋만). **백엔드 변경이므로 서버 재시작이 필요하다.**

## 알려진 범위

- **실제 로그인(비밀번호 입력)할 때만** 지급한다. 로그인 토큰이 7일간 유지돼 로그인 화면을 거치지 않고 계속 쓰는 사람은 받지 못한다(요청 문구 그대로). 사이트에 들어올 때마다 받게 하려면 토큰 복원 시점에도 호출하는 별도 변경이 필요하다.
- 소급 지급 없음. 포인트 누적·원장은 배포 이후부터.

## 수동 테스트

1. 로그인 → "출석체크 완료! +10P" 알림, 행운 뽑기 포인트가 10 늘었는지
2. 같은 날 로그아웃 후 다시 로그인 → 알림 없음, 포인트 그대로
3. 관리자 → 행운 뽑기 관리 → 해당 회원 포인트 내역에 "출석체크" 1건
4. 한국 시간 자정 이후 로그인 → 다시 지급
