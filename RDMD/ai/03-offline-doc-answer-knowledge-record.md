# AI 서버 OFF 알림 + 꺼져도 지식 문서로 답하기 + 지식(knowledge) 고도화

> 앞선 기록: [01](./01-ai-service-record.md)(첫 버전) · [02](./02-ollama-chromadb-record.md)(Ollama·ChromaDB). 기능 설명 [`../features/ai-service.md`](../features/ai-service.md).

## 요청

> Ollama 서버가 꺼져 있으면 **"AI 서버 OFF 상태 (사이트의 정보내용을 끌어다 대답합니다.)"** 라고 알림을 내고, 알림대로 정말로 `ai-service/knowledge` 의 내용으로 답하게 해 줘. 그리고 `knowledge` 를 더 고도화하자.

## 변경

### 1. AI 서버 ON/OFF 감지 · 알림

| 영역 | 내용 |
|---|---|
| ai-service | `service/llm_status.py` — Ollama `GET /api/tags`(2초 제한)로 켜짐·모델 존재 확인, ON 10초·OFF 5초 기억, LLM 호출 실패 시 즉시 OFF(`failed()`)·성공 시 ON(`succeeded()`). provider 별: anthropic=키 유무, none=항상 OFF. OFF 사유 `reason`(unreachable·model_missing·disabled·no_key) |
| ai-service | `GET /status`(`{ai, reason, provider, model, vector_ready, documents}`), `POST /chat` 응답에 `ai: on\|off`, `/health` 에 `ai` |
| Express | `GET /api/ai/status` → `{ ai: 'on'\|'off'\|'down' }`(down = ai-service 자체가 꺼짐), `/api/ai/chat` 응답에 `ai` 전달 |
| 화면 | `AiHelper.jsx` 상단 알림 바 — ON "AI 서버 ON"(초록 점) · **OFF "AI 서버 OFF 상태 (사이트의 정보내용을 끌어다 대답합니다.)"**(주황) · down(빨강). 들어올 때 + 20초마다(탭이 보일 때) 확인, 답이 오면 그 상태로 즉시 갱신, 503 이면 down. 답 아래 배지 "AI 서버 OFF — 사이트 지식 문서에서 그대로 가져온 답이에요" |

### 2. OFF 일 때 지식 문서로 답하기

- `service/graph.py` `generate` 에 `gate`(LlmStatus) — **OFF 면 LLM 을 부르지 않고 바로 문서 답**(예전에는 호출을 시도하다 실패해야 문서 답으로 갔다. 주소가 막혀 있으면 3분을 기다릴 수 있었음).
- `service/doc_answer.py` — 답 만들기: 캐릭터 질문 = `tiers.json` 정확한 한 줄 + 티어표 안내, 그 외 = 검색된 문서 위쪽 1~2개에서 **질문의 주제어와 겹치는 줄만**(짧은 문서 300자 이하는 통째로, 길면 겹치는 줄만 예산 650자 안에서, 티어 목록은 1600자까지) 출처 제목(`▸`)과 함께. 둘째 문서는 주제어가 2개 이상 겹칠 때만. 실제로 보여 준 문서만 `sources` 로.
  - 이전 버전은 첫 700자를 잘라 보여 줬다 → 질문과 상관없는 줄이 섞였다.
- `service/retrieval.py` — `available` 콜백: OFF 면 **벡터 검색(임베딩)도 시도하지 않는다**(같은 Ollama 라서). `lexical_clean` 추가.
- 범위 판단(벡터를 못 쓸 때): `service/knowledge.py` `strip_question_words()` 로 "어때·알려줘·하면" 같은 군더더기를 뺀 질문의 BM25 점수가 `MIN_LEXICAL_CLEAN = 12` 이상이어야 사이트 질문. (예전에는 BM25 총점 10 이라 "오늘 날씨 어때?" 가 "오늘의 행운 티어" 문서로 답해졌다.)

### 3. 지식(knowledge) 고도화 — 8개 → 14개 파일, 조각 382 → 469

| 신규 | 내용 |
|---|---|
| 09 FAQ | 31개 질문(`##` 하나가 질문 하나) |
| 10 용어집 | 같은 말 다른 표현(출첵·비번·가챠·캡처·랭킹·사다리 …) |
| 11 단계별 사용법 | 12가지 작업의 번호 순서 |
| 12 문제 해결 | 21가지 증상 |
| 13 공지·문의·신고·알림 | 기존 지식에 없던 소통 기능 |
| 14 사이트 업데이트 이력 | 1.0.0 ~ 1.0.5 |

기존 파일 보강: 01(테마 자동 전환·홈 화면 추가·후원·버전), 03(PNG 는 채운 등급만 등급별 파일/PDF 는 한 파일), 05(**족보 16종 전부 + 설명**), 07(마이페이지 진입 문구).

- **동기화 테스트** `tests/test_knowledge_sync.py`(6개): 서버 코드의 확률·포인트표·한도·포커 족보 배수·랜덤 뽑기 배수·출석 포인트·퀴즈 상금표·자동 로그아웃·질문 제한을 읽어 지식 문서와 비교.
  - 처음 돌리자마자 **지식에 "파이브 플러시(배수 10)" 가 빠져 있던 것**이 드러났다(족보는 15가지가 아니라 16가지). 같은 오류가 내가 10-02 에 쓴 `RDMD/features/luck-draw.md`("족보 15종")에도 있어 함께 고쳤다.
- 사실 확인: 화면 문구·서버 응답을 코드에서 확인해 썼다. 확인되지 않는 것은 쓰지 않았다(가입 인증 링크 만료 시 대처법은 "따로 안내되어 있지 않아요"). 작성 중 바로잡은 것: 문의하기는 로그인 필요, 답변 수정은 운영진만, 마이페이지 진입 문구(데스크톱 "마이페이지"/모바일 "프로필 보기"), 로그인이 안 되는 사람에게 "문의하기" 를 권하는 모순.

## 실측 · 기준값

- 469조각 재측정: 사이트 질문 벡터 유사도 0.53~0.80, 범위 밖 0.37~0.50 → `MIN_VECTOR_SIM` 0.50 → **0.52**. 고도화로 말을 바꿔 묻는 질문의 유사도가 올랐다("출첵 하면 몇 점 줘?" 0.666→0.745, "비번 까먹었어" 0.663).
- OFF 상태 점검(가짜로 꺼진 Ollama 주소): 질문 8개가 0~2초 — 출첵(1~7일차 포인트 전부) · 닉네임 7일 · 비번 까먹었어(FAQ) · 알림 끄는 법 · 포커 단계 · 사진으로 저장(용어집) 등 지식 문서 문장 그대로, 날씨는 거절, 캐릭터는 티어 정확.
- ⚠ OFF 한계: 임베딩이 없어 **지식 문서에 없는 구어체는 못 찾는다**("스트릭이 끊겼어" 거절). 그래서 FAQ·용어집에 별칭을 넣었다. "포커 족보 배수" 는 단계별 설명이 먼저 나오고 배수표는 둘째 문서로 나온다(제목에 "족보와 배수" 를 넣어 보강).

## 찾아 고친 문제

1. **서비스가 계속 죽었다** — 같은 `data/chroma` 를 점검 스크립트(별도 프로세스)가 함께 열면 서비스가 종료됐다(Chroma 의 로컬 파일은 프로세스 하나만 쓰는 전제). 스크립트는 `data/chroma-scripts` 를 쓰게 했다. 또 PowerShell 로 띄운 uvicorn 이 터미널 쪽 Ctrl+C 에 같이 꺼지는 일이 있어 `scripts/dev_service.py`(떼어서 띄움·상태·종료)를 만들었다.
2. `.env` 의 첫 줄이 `#` 없이 시작해 chromadb(python-dotenv)가 경고를 낸다(무해, 사용자 파일이라 손대지 않음).
3. 첫 구현의 문서 답은 둘째 문서가 거의 항상 끼었다 → 주제어 2개 이상 겹칠 때만, 출처도 보여 준 문서만.

## 확인

- `pytest` 42개 통과(+ 지식 동기화 6, OFF 모드 13: 상태 ON/OFF/모델 없음/캐시/실패 전환, OFF 면 LLM 미호출, 문서 줄 고르기, 군말 제거, 벡터 시도 안 함, `/status`·`ai` 필드).
- 실제 서비스 2개(ON: 실제 Ollama, OFF: 꺼진 주소) + 실제 Express + 빌드된 화면을 Chrome(PC·모바일)으로: 알림 문구가 정확히 나오고(ON/OFF), OFF 에서 질문 시 배지와 참고가 맞게 나옴.

## 한계

- 실제 Ollama 를 껐다 켜는 시험은 하지 않았다(가짜로 꺼진 주소로 대신 — 사용자의 Ollama 를 건드리지 않으려고). 켜진 상태→꺼짐 전환(캐시 5~10초 뒤 반영)은 단위 테스트로만 확인.
- 지식은 사람이 쓰는 문서라 사이트가 바뀌면 같이 고쳐야 한다. 동기화 테스트는 **수치**만 지킨다(문구·메뉴 이름은 못 지킴).
