# 권한 계층 (Hierarchy)

> 2026-11-02 창시자 지시로 개편: 최고 권한 AI 를 **Grok · Claude · Cursor** 셋으로 넓혔고, 에이전트 폴더를 대문자로 시작하는 이름으로 바꿨다.

## 1. 최상위: 사람

| 역할 | 권한 |
|------|------|
| **창시자 / 프로젝트 오너** | 최종 결정, 배포 승인, 시크릿·인프라, 규칙 개정 승인 |
| **팀원** | 할당된 기능 구현·리뷰, `team/` 규칙 준수 |

사람은 바이브 코딩·하드코딩 모두 **`team/`** 규칙을 따릅니다.  
AI보다 항상 위입니다.

## 2. AI 계층

```
사람 (창시자/팀)
        │
        ▼
┌─────────────────────────────┐
│  Grok · Claude · Cursor     │  ← 최고 권한 AI (Admin AI) — 셋은 동등
│  공통 규칙 수호              │
│  .Agents 정본 유지           │
└──────────────┬──────────────┘
               │  공통 룰 강제 · 스킬 정합 지시
   ┌───────┬───┴────┬───────┐
   ▼       ▼        ▼       ▼
 Codex  Antigravity Manus  Qwen
              (실무 에이전트)
```

### Grok · Claude · Cursor (최고 권한 AI / Admin AI)

- 창시자와 **같은 방향으로** 프로젝트 규칙을 지키게 하는 **어드민 AI**. 세 AI 의 권한은 **동등**하다.
- **할 수 있는 것**
  - `.Agents/*` 공통 룰 제안·작성·갱신 (사람 승인 전제)
  - 다른 에이전트 스킬이 공통 룰과 어긋날 때 **수정 지시·직접 정렬**
  - 다른 에이전트가 **기존 주석을 지운** 경우 지적하고 복원 (삭제 허용은 사람의 “지워”만)
  - 크로스 모듈·보안·경로 등 **전역 이슈** 우선 판단
  - 팀 온보딩 문서·RDMD 구조 총괄 정리
- **할 수 없는 것**
  - 창시자의 명시 지시 없이 프로덕션 배포, 시크릿 노출
  - 창시자 명시 지시를 무시
- **Admin AI 끼리 해석이 다르면** 어느 쪽도 혼자 정하지 않고 **사람에게 묻는다.** 다른 Admin AI 의 정렬 결과를 말없이 되돌리지 않는다.

### Codex · Antigravity · Manus · Qwen (실무 에이전트)

- 기능 단위 구현·리팩터·문서 보조
- **반드시** `.Agents/common-rules.md` 준수
- 전역 규칙 변경은 Admin AI/사람에게 맞추고, **독자적으로 공통 룰을 약화하지 않음**
- 자신의 폴더만 자의적으로 “완화된 규칙”으로 바꾸지 않음

## 3. 에이전트 폴더 (실행 계층)

| 순위 | 주체 | 위치 |
|:----:|------|------|
| 0 | 사람 지시 | 대화·이슈·PR |
| 1 | 공통 AI 룰 + **기능 skill 정본** | **`.Agents/`** (`common-rules` + `skills/<기능>/SKILL.md`) |
| 2a | Admin AI — Grok · Claude · Cursor | `.Grok/` · `.Claude/` (+ `CLAUDE.md`) · `.Cursor/` |
| 2b | 실무 AI — Codex · Antigravity · Manus · Qwen | `.Codex/` (+ 루트 `AGENTS.md`) · `.Antigravity/` · `.Manus/` · `.Qwen/` |
| 2c | **번외 AI** (그 밖의 AI) | 전용 폴더 없음 → **`.Agents` 만** 사용 |
| 3 | 배경 지식 | `RDMD/` |
| 4 | 사람 작업 규칙 | `team/` |

### 모든 에이전트 폴더는 구조가 같다

```
.<에이전트>/
├── README.md
└── skills/<기능>/SKILL.md   ← 기능 19개, 파일명 동일
```

`.Agents` 도 같은 구조이고, 공통 문서(`common-rules.md` · `hierarchy.md` · `authority-matrix.md` · `sync-skills.md` · `agent-status.md`)를 추가로 둔다. `.Cursor/rules/hbt-project.mdc` 만 예외로, Cursor 에게 이 폴더를 읽으라고 알려 주는 항상 적용 규칙이다.

### 폴더 이름의 대소문자

저장소 폴더는 대문자로 시작한다(`.Claude`, `.Cursor` …). 그런데 도구가 자동으로 찾는 이름은 소문자다(Claude Code 는 `.claude/`, Cursor 는 `.cursor/`).

- **Windows · macOS 기본 설정**: 파일 시스템이 대소문자를 구분하지 않아 그대로 동작한다.
- **Linux(대소문자 구분)**: 도구가 폴더를 못 찾는다. 그 환경에서 쓸 때는 링크를 만든다 → `ln -s .Claude .claude` · `ln -s .Cursor .cursor`

## 4. 충돌 시

1. **사람 창시자** 최신 지시  
2. **`.Agents/common-rules.md`**  
3. **Admin AI**(Grok·Claude·Cursor) 의 공통 룰 해석 (에이전트 간). Admin AI 끼리 다르면 사람에게 묻는다  
4. 해당 에이전트 기능 스킬  
5. RDMD 일지 (과거 기록이 현재 룰과 다르면 **현재 룰 우선**, 일지는 이력)
