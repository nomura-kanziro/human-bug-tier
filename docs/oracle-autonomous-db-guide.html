Autonomous Database 만들고 웹앱에 연결하기

지금 쓰고 있는 OCI 인스턴스(웹 서버) 옆에 무료 Oracle DB를 하나 만들고, 서버 코드가 그 DB에 접속하게 하는 전체 흐름이에요. 콘솔에서 할 일, AI에게 알려 줄 정보, 지켜야 할 보안 규칙을 순서대로 정리했어요.

1. 전체 구조2. DB 만들기3. AI에게 요청하기4. 비밀번호와 지갑5. 주의할 점
1

전체 구조 한눈에 보기

누가 누구에게 접속하는지, 지갑 파일이 어디로 옮겨지는지를 그렸어요.

인스턴스이미 만든 웹 서버예요. 코드, .env, 지갑 폴더가 여기에 있어요.
Autonomous DBOracle이 관리해 주는 DB예요. 서버를 따로 만들지 않고 콘솔에서 바로 만들어요.
지갑 (Wallet)DB 접속용 인증서와 주소가 든 zip 파일이에요. 열쇠라서 Git에 올리면 안 돼요.
웹앱Node 앱이 .env의 값과 지갑을 읽어서 DB에 접속해요. 인스턴스의 기본 아웃바운드 규칙으로 1522 포트 접속이 가능해요.
2

콘솔에서 DB 만들기

인스턴스를 만든 리전(서울 또는 춘천)과 같은 리전에서 만드세요. 홈 리전에서만 Always Free를 쓸 수 있어요.

☰ 왼쪽 위 메뉴→ Oracle Database→ Autonomous Database→ Create Autonomous Database

콘솔 개편 때 메뉴 이름이 조금 바뀔 수 있어요. 안 보이면 위쪽 검색창에 Autonomous Database를 입력하세요. 왼쪽의 Compartment가 인스턴스와 같은지도 확인하세요.

  1. 기본 정보 입력

    Display name
    hbt-db (콘솔에 보이는 이름)
    Database name
    hbtdb (영문·숫자만, 14자 이하. 서비스명 앞부분이 돼요)
    Compartment
    인스턴스와 같은 곳

  2. 워크로드와 배포 방식 고르기

    Workload type
    Transaction Processing (웹 서비스용. 회원, 투표, 게시글 같은 짧은 읽기·쓰기에 맞아요)
    Deployment type
    Serverless

  3. Always Free 켜기

    Always Free
    스위치 켜기
    무료 한도
    계정당 DB 2개, 각각 저장공간 20 GB, CPU 고정(자동 확장 불가)
    Database version
    기본값(가장 최신)

    스위치를 켜면 CPU, 스토리지 칸이 회색으로 잠겨요. 잠기지 않았다면 Always Free가 꺼진 상태라 요금이 나갈 수 있어요.

  4. ADMIN 비밀번호 정하기

    Username
    ADMIN (고정)
    규칙
    12~30자, 대문자·소문자·숫자 각 1개 이상, 큰따옴표(")와 admin 단어는 쓸 수 없어요

    비밀번호 관리자에 바로 저장하세요. ADMIN은 관리용이고, 앱에서는 나중에 만드는 전용 계정(HBT_APP 등)을 쓰는 게 안전해요.

  5. 네트워크 접근 정하기

    Access type
    Secure access from allowed IPs and VCNs only
    허용할 IP
    인스턴스 공인 IP, 그리고 내 PC에서 테스트할 거라면 내 집 IP
    Require mTLS
    처음에는 켜 둔 채로 두세요 (지갑 방식, 아래 3장 참고)

    "Secure access from everywhere"도 지갑이 있어야 접속되니 안전하지만, IP를 제한하면 한 겹 더 막을 수 있어요. 집 IP가 바뀌면 여기서 다시 추가하면 돼요.

  6. Create 누르고 기다리기

    상태가 Provisioning → Available(초록색)로 바뀌면 끝이에요. 보통 2~5분 걸려요.

  7. 지갑(Wallet) 다운로드

    위치
    DB 상세 화면 → Database connection 버튼 → Wallet type은 Instance wallet → Download wallet
    지갑 비밀번호
    새로 정하는 비밀번호예요 (ADMIN 비밀번호와 다르게). 이것도 비밀번호 관리자에 저장
    받은 파일
    Wallet_hbtdb.zip → 압축을 풀면 tnsnames.ora, cwallet.sso, ewallet.pem, sqlnet.ora 등이 나와요

    같은 화면 아래쪽 Connection strings 표에서 hbtdb_low, hbtdb_medium, hbtdb_high 같은 서비스명을 볼 수 있어요.

  8. 지갑을 서버로 복사

    PC에서 압축을 푼 폴더를 인스턴스로 올리고, 다른 사용자가 못 읽게 권한을 잠가요. 키 파일 이름과 IP는 본인 값으로 바꾸세요.

    # 내 PC (PowerShell)
scp -i ~/.ssh/oci_hbt -r .\wallet ubuntu@<인스턴스_공인IP>:~/hbt-wallet

# 서버 (SSH 접속 후)
chmod 700 ~/hbt-wallet
chmod 600 ~/hbt-wallet/*
서비스명특징언제 쓰나
hbtdb_low 추천동시 접속을 가장 많이 받고, 쿼리 하나당 CPU를 적게 써요웹앱 기본 연결
hbtdb_tpTransaction Processing 전용, low와 비슷해요짧은 읽기·쓰기 위주 앱
hbtdb_medium동시 접속 수가 제한되고, 쿼리당 CPU를 더 써요통계, 랭킹 집계
hbtdb_highCPU를 가장 많이 쓰고, 동시에 몇 개만 실행돼요가끔 하는 무거운 작업

AI에게 연결 코드를 부탁할 때

아래 정보가 있으면 AI가 한 번에 맞는 코드를 써 줄 수 있어요. 비밀번호 값은 하나도 필요 없어요.

  • 언어 / 프레임워크웹 백엔드는 Node.js + Express, AI 서비스는 Python (ai-service)
  • 리전예: ap-seoul-1 (서울) 또는 ap-chuncheon-1 (춘천)
  • DB 이름과 서비스명hbtdb, 쓸 서비스명은 hbtdb_low
  • 지갑 위치서버: /home/ubuntu/hbt-wallet, PC: D:\vscode\human_bug_tier\wallet
  • mTLS 또는 TLS지갑을 쓰면 mTLS, 지갑 없이 쓰면 TLS (아래 설명)
  • 필요한 테이블예: users, tiers, votes. 컬럼이 정해졌다면 같이 적기
  • 배포 위치OCI 인스턴스(E2.1.Micro, PM2 실행)인지, PC에서만 테스트인지
  • .env 변수 이름값 말고 이름만. 아래 템플릿에 들어 있어요
방식지갑콘솔 설정고르는 기준
mTLS 기본필요 (wallet/ 폴더)Require mTLS 켬처음 시작할 때. 어디서든 안전하게 접속
TLS필요 없음허용 IP 등록 + Require mTLS 끔지갑 파일 관리가 귀찮고, 접속하는 IP가 고정일 때

복사해서 AI 채팅에 붙여넣는 요청 템플릿 · <꺾쇠> 부분만 고치세요

human-bug-tier 웹앱을 Oracle Autonomous Database에 연결하는 코드를 만들어 줘.

[환경]
- 언어/프레임워크: Node.js + Express (backend/server.js). 드라이버는 node-oracledb Thin 모드
- 리전: <ap-seoul-1>
- DB: Autonomous Database (Always Free, Transaction Processing)
- DB 이름: hbtdb / 서비스명: hbtdb_low
- 접속 방식: mTLS (지갑 사용)
- 지갑 위치: 서버 /home/ubuntu/hbt-wallet, 로컬 D:\vscode\human_bug_tier\wallet
- 배포 위치: OCI 인스턴스 (Ubuntu, E2.1.Micro 1GB, PM2로 실행, Nginx 뒤)

[비밀 값] 값은 내가 .env에 직접 넣을게. 코드에서는 아래 변수 이름만 써 줘.
- ORACLE_USER
- ORACLE_PASSWORD
- ORACLE_CONNECT_STRING   (예: hbtdb_low)
- ORACLE_WALLET_DIR
- ORACLE_WALLET_PASSWORD

[필요한 테이블]
- <users (id, nickname, created_at)>
- <tiers (id, name, rank)>
- <votes (id, user_id, tier_id, created_at)>

[요청]
1. 커넥션 풀을 만드는 db.js (메모리가 1GB라 poolMax는 작게)
2. 위 테이블을 만드는 SQL. ADMIN 말고 앱 전용 사용자(HBT_APP)를 만드는 SQL도 같이
3. 연결 확인용 GET /api/db-health 라우트
4. .env.example 파일과 .gitignore에 추가할 줄
5. 서버에서 실행·확인하는 명령어
4

비밀번호와 지갑 지키기

DB 비밀번호와 지갑은 서버 열쇠와 같아요. 한 번 새어 나가면 DB 전체를 읽고 지울 수 있어요.

하지 마세요

  • ADMIN 비밀번호, 지갑 비밀번호를 AI 채팅에 붙여넣기
  • .env 파일 내용을 통째로 복사해서 보여 주기
  • 지갑 zip이나 wallet/ 폴더를 GitHub에 올리기
  • 코드 안에 비밀번호를 직접 적기

이렇게 하세요

  • AI에게는 ORACLE_PASSWORD 같은 변수 이름만 알려 주기
  • 값은 서버와 PC의 .env에 내가 직접 입력
  • 값 없이 이름만 적은 .env.example은 커밋해도 돼요
  • 실수로 올렸다면 콘솔에서 비밀번호 변경 + Rotate wallet

.gitignore 맨 아래에 추가 (지금 레포에는 .env는 있고 지갑 규칙은 없어요)

# ============================================
# Oracle Autonomous DB 지갑 (절대 커밋 금지!)
# ============================================
wallet/
Wallet_*/
Wallet_*.zip
*.sso
*.p12
*.jks
ewallet.pem

.env (서버와 PC에 각각, 값은 직접 입력)

ORACLE_USER=HBT_APP
ORACLE_PASSWORD=          # 직접 입력, 채팅에 붙여넣지 않기
ORACLE_CONNECT_STRING=hbtdb_low
ORACLE_WALLET_DIR=/home/ubuntu/hbt-wallet
ORACLE_WALLET_PASSWORD=   # 지갑 다운로드 때 정한 비밀번호

Always Free DB가 멈추거나 지워지는 경우

무료 DB는 아무도 안 쓰면 Oracle이 자동으로 멈추고, 오래 멈춰 있으면 회수해 가요.

사용 중

앱이나 SQL 도구로 접속이 있으면 계속 켜져 있어요.

7일 동안 접속 없음 → 중지

자동으로 Stopped가 돼요. 콘솔에서 Start를 누르면 데이터 그대로 다시 켜져요.

중지 상태로 3개월 → 삭제 가능

Oracle이 DB를 회수할 수 있어요. 지워지면 데이터는 되살릴 수 없어요.

  • 사이트가 운영 중이면 걱정 없어요방문자가 있으면 앱이 계속 접속하니까 7일 조건에 안 걸려요
  • 개발만 하는 동안에는일주일에 한 번은 접속하거나, 서버 cron으로 하루 한 번 /api/db-health를 호출하세요
  • 중지 알림 메일 확인Oracle이 중지·삭제 전에 계정 메일로 알려 줘요
  • 중요한 데이터는 따로 백업Always Free는 자동 백업 복원이 제한돼요. 가끔 Data Pump나 CSV로 내보내 두세요
2026년 11월 기준 Oracle Cloud 콘솔 화면으로 정리했어요. 메뉴 이름이나 무료 한도는 Oracle 정책에 따라 바뀔 수 있으니, 생성 화면의 Always Free 표시를 꼭 확인하세요.
